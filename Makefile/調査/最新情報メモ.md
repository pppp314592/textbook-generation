### 4.4 で導入された主な新機能（NEWSより、出典: GNU FSF, 2023-02-26）
| 機能 | 説明 |
|---|---|
| `.WAIT` 特殊ターゲット | 前提条件リスト中に置くと、左側の前提が完了するまで右側を開始しない |

| `.NOTINTERMEDIATE` | 中間ファイル扱いを無効化 |
| `$(let ...)` / `$(intcmp ...)` 関数 | ローカル変数・数値比較の新関数 |
| `--shuffle[=mode]` | 前提条件・ゴールを並べ替えて並列ビルドのファジングテスト（random/reverse/seed/none） |
| `--jobserver-style=fifo|pipe` | FIFOによるジョブサーバー |
| 暗黙ルール探索アルゴリズム改善 | "ought to exist" の扱い変更 |
| `--debug=print` / `--debug=why`、`--trace` | デバッグ強化 |
| `MAKE_TMPDIR` 環境変数 | 一時ファイル用ディレクトリ |

- 4.4.1 はバグ修正版（ar並列ビルド対応、z/OS対応追加、FIFOジョブサーバーの一部無効化など）

### 誤解の修正（重要）
- `!=` 代入演算子 → **4.0（2013年）で導入**
- `$(file)` 関数の読み込み改善 → **4.2（2016年）で導入**（書き込みは4.0）

### 変化・更新点
- 4.4で非推奨化されたOS（OS/2・AmigaOS等）のうちAmigaOSは開発版4.4.90でサポート削除
- 将来の後方非互換の予告: パターンルールの複数ターゲットがグループ化ターゲット（`&:`）と同挙動に変更予定（4.5以降）
- 開発版のみの機能（安定版未リリース）: `--warn`、`--print-targets`、`.WARNINGS`、条件付き代入の一般化（`?:=`等）
  ※教科書に書く場合は「最新開発版の機能」と明記必要

## 2. Makefileのベストプラクティス（2026年時点）

### 最新情報（確認済み）
- **依存関係自動生成**: マニュアル§4.14「Generating Prerequisites Automatically」が公式推奨
  - GCCの `-MMD -MP -MF` はGCCマニュアル「Preprocessor Options」に記載
    - `-MMD`: システムヘッダ除外で `.d` を生成
    - `-MP`: ダミーphonyターゲット付与（ヘッダ削除時のエラー回避）
    - `-MF file`: 出力先指定
  - 実践: `$(OBJS:.o=.d)` を `-include` で読み込む
  - 出典: https://gcc.gnu.org/onlinedocs/gcc/Preprocessor-Options.html
- **並列実行**: `-j`（§5.4）、`--output-sync`/`-O` は none|line|target|recurse の4段階
  - 4.4 の `--shuffle` をCIで併用して前提条件の漏れを検出するのが2026年時点の推奨
- **.PHONY / 自動変数（$@ $< $^ $? $|）/ パターンルール / 静的パターンルール / 二次展開（.SECONDEXPANSION）**: すべてマニュアル対応章に記載
- **$(call) $(eval) $(foreach) $(shell) $(wildcard) $(file) $(let)**: マニュアル§8.1〜8.14
- **VPATH / vpath**: §4.5 Directory Search
- **GNU Coding Standards「Makefile Conventions」**が公式慣習（CC/CFLAGS抽象化、標準ターゲット all/clean/install/uninstall/check、DESTDIR対応）
  - https://www.gnu.org/prep/standards/html_node/Makefile-Conventions.html
- **POSIX.1-2024（IEEE Std 1003.1-2024）のmake規定**が「.POSIX付きで書けば可搬」の公的基準

### 変化・更新点
- 依存自動生成は手動 `make depend` から、GNU makeのmakefile自動再生成により常時自動へ移行済み
- マニュアルがPOSIX.1-2024参照に更新（2024-08）

### 信頼性
確認済み（GNU/FSF公式）。「2026年時点のベストプラクティス」の規範的記述は公式資料からの導出。

## 3. 他ツールとの比較・関連（2026年時点の実勢）

### Makeとの関係
- **CMake**: C++の事実上の標準ビルドシステム。Make・Ninja両方をジェネレータとして出力。MakefileはCMakeの生成物としても生き続けている
- **Ninja**: 「スピード重視の小さいビルドシステム。入力は上位ビルドシステムが生成することを前提」「Ninjaはアセンブラ」。Chrome・Android・LLVM等で使用
- **Bazel**: 大規模モノレポ・リモート実行・サンドボックス志向。学習コスト大、中規模以下には過剰
- **Task / Just**: 「Makeに着想を得たクロスプラットフォームのコマンドランナー」。タイムスタンプ依存のビルド判定ではなく「タスクの実行」に特化。YAML（Task）／独自構文（Just）

### Makeが今も使われる理由
- POSIXの一部であり、Linux/macOS/BSDにデフォルト同梱＝ゼロインストール
- Autotools・GNU Coding Standardsがmakeを前提
- 40年以上の蓄積（1976年Stuart Feldman開発。1977年説も流通）
- 弱点: TAB依存・シェル依存レシピ・依存追跡の手間・再帰makeの複雑さ・並列時の非決定性（→4.4の--shuffleで緩和）

### 信頼性
確認済み（各ツール公式ページ）。「Makeが今も使われる理由」の評価部分は要確認。

## 4. プラットフォーム差異

### 最新情報（確認済み）
- **Linux**: GNU make標準同梱。最新4.4.1（ディストロにより4.3/4.4系）。レシピのシェルは/bin/sh、`.SHELLFLAGS` 既定値は `-c`（.POSIX指定時 `-ec`）
- **Windows**:
  - GNU makeは標準構成に含まれない。選択肢: **NMAKE**（Visual Studio付属）、**MSYS2/MinGW**、**Cygwin**、**WSL**
  - WindowsではSHELL環境変数がmakefileから参照される（Unixでは意図的に無視）
  - 4.4のジョブサーバーはWindowsで名前付きセマフォ方式（`--jobserver-style=sem`）
  - `mkdir -p`・`rm -rf` はcmd.exeでは動かないため、MSYS2/Cygwinのsh.exe経由かシェル非依存に書く必要あり
  - 出典: https://learn.microsoft.com/en-us/cpp/build/reference/nmake-reference 、https://www.msys2.org/
- **WSL**: `wsl --install` でLinux版GNU makeをそのまま実行可能
  - 出典: https://learn.microsoft.com/en-us/windows/wsl/install （更新2026-06-02）
- **macOS**: Homebrewのmake formulaは「システムのmakeを置き換えるため gmake として導入」と明記。stableは4.4.1
  - 出典: https://formulae.brew.sh/formula/make

### 変化・更新点
- POSIX.1-2024で `.WAIT`、`!=`、`::=`、`:::=`、`?=`、`+=` が標準仕様に取り込まれた
- 4.4で `--print-directory` の優先順位、makefile再構築の順序、`MAKEFLAGS` の内容が後方非互換で変更

### 信頼性
確認済み。macOS同梱バージョンとWindowsパス区切り挙動は要確認。

## 5. 中級者が学ぶべき落とし穴

1. **タブ文字とスペース**: レシピ行は必ずTAB始まり（スペースNG）。`$(.RECIPEPREFIX)` で変更可能（3.82+）
2. **レシピのシェル実行**: 行ごとに別シェルで実行（`.ONESHELL` で1シェル化、3.82+）。シェル変数は `$$var`、make変数は `$(var)`
3. **代入演算子**: `=`（再帰展開）／`:=`（即時展開）／`::=`（POSIX即時展開）／`?=`（未定義時のみ）／`+=`（追記）／`!=`（シェル実行）。4.3以降 `+=` は空変数への追記で先頭スペースを付けない（後方非互換）
4. **`.DEFAULT_GOAL`**: 既定ゴールの明示設定（3.81+）。.dファイルのincludeを先頭に置くと意図しない最初のターゲットが既定ゴールになる罠
5. **再帰的makeと `$(MAKE)`**: サブmakeは `$(MAKE)` を使う（MAKEFLAGS・ジョブサーバー継承のため）
6. **`.PHONY` 忘れ**: clean等と同名ファイルがあるとレシピが走らない
7. **暗黙ルールの罠**: C系の組み込みルールが意図しないターゲットに適用される。`-r`/`-R`、`.SUFFIXES:` で無効化
8. **並列ビルドの非決定性**: 前提条件の宣言漏れが-jで再現しない → `--shuffle`（4.4）で検出、`.NOTPARALLEL`・`.WAIT` で対策
9. **関数の罠**: `$(shell)` は改行をスペース化、`$(wildcard)` は4.3以降ソート済み、`$(call)` の引数は `$1`〜、`$(eval)` の即時/遅延展開の区別
10. **バージョン間の後方非互換（NEWSのWARNING群）**: 4.4のifeqカンマ解析・グループ化ターゲット・MAKEFLAGS／4.3の関数内`#`・ワイルドカードソート／4.0の`!=`・`::=`／3.81の二次展開

### 信頼性
確認済み（NEWS・マニュアル・POSIX一次資料）

## 総括（教科書への反映上の注意）
- 「4.4の新機能」として `!=` と `$(file)` を書くと誤り。`!=`は4.0、`$(file)`読み込みは4.2。4.4の代表的新機能は `--shuffle`・`.WAIT`・`$(let)`・`$(intcmp)`・`--jobserver-style`
- 最新安定版は4.4.1（2023-02-26）で2026年7月時点でも最新。開発版（4.4.90系）の機能は「未リリース」として扱う
- 2024年のPOSIX.1-2024がmakeを大幅拡張（.WAIT・代入演算子の標準化）した点は新規に強調すべき論点
- 要確認3点: macOS同梱makeの版数／Windowsのバックスラッシュ挙動の一次資料／Make使用実態の統計的裏付け
