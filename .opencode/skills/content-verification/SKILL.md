# 内容検証スキル

生成した教科書の内容を `content-verifier` サブエージェントに検証させる。

## テーマフォルダ構成

検証結果はテーマごとのフォルダに配置する。

```
{作業ディレクトリ}/
└── {テーマ名}/
    ├── README.md              # テーマ概要・進行状況（検証結果も記録）
    ├── 教科書.md              # 検証対象の教科書本体
    └── 検証レポート.md        # 検証結果
```

- 対象のテーマフォルダが無い場合は作成する。
- 検証結果は `{テーマ名}/検証レポート.md` に保存する。既に存在する場合は追記して再検証日を記録する。

## 手順

1. **対象の確定**
   - 検証対象のファイルパスと、作成時に設定した対象レベル・章数・テーマを確認する。
   - テーマフォルダを特定する。対象が未確定なら、`{テーマ名}/教科書.md` を探して特定する。

2. **サブエージェントの起動**
   - `content-verifier` サブエージェントに以下の情報を渡して検証を依頼する:
     - 検証対象のファイルパス（1つまたは複数）
     - テーマ、対象レベル、対象読者
     - 依頼したい検証項目（指定がなければ全項目）
   - 検証項目は以下:
     1. **事実の正確性**: 不確かな事実・誤りを含む記述。不明な点は websearch/webfetch で裏取り
     2. **内部整合性**: 章間・本文・練習問題・解答・用語集の相互の矛盾（例: 用語の定義ずれ、問題番号の対応）
     3. **構成の妥当性**: 章立ての順序・網羅性・分量バランス
     4. **レベル適合性**: 対象読者に対して語彙・説明の深さが適切か
     5. **品質**: 誤字脱字、表記揺れ、リンク切れ、未完の箇所（TODO等）

3. **結果の保存と反映**
   - サブエージェントの報告（問題点リストと修正提案）を要約して `{テーマ名}/検証レポート.md` に保存する。
   - 検証レポートには検証日、対象ファイル、検証項目、問題リスト、対応状況（未対応/修正済み）を含める。
   - 重大な問題（誤った事実、矛盾）はその場で修正する。
   - 修正したら、必要に応じて再検証を1回実行して修正漏れがないか確認する。
   - `README.md` の進行状況を更新する。

## 報告フォーマット

検証結果は以下で整理して返す:

```
## 検証結果
- 重大: N件 / 軽微: N件
- 問題点: (重要度) 箇所 内容 → 修正提案
- 修正済み/未修正 の区分
```

- 重大 = 誤った事実・深刻な矛盾・学習を妨げる問題
- 軽微 = 表記揺れ・スタイル・改善提案レベル
