# 教科書作成スキル

ユーザーが指定したテーマに基づき、学習用の教科書をMarkdown形式で生成する。

## テーマフォルダ構成

テーマごとに専用フォルダを作成し、生成物はすべてその中に整理して配置する。

```
{作業ディレクトリ}/
└── {テーマ名}/                # テーマごとのフォルダ（新規作成）
    ├── README.md              # テーマ概要・対象読者・進行状況・ファイル構成
    ├── 教科書.md              # 教科書本体（Markdown）
    ├── 検証レポート.md         # 内容検証の結果（content-verification が作成）
    ├── 調査/
    │   └── 最新情報メモ.md    # 最新情報収集の結果（latest-info-collection が作成）
    ├── 印刷用/
    │   ├── 教科書-印刷版.html # A4印刷用HTML（print-formatting が作成）
    │   └── 教科書.pdf         # PDF（print-formatting が作成）
    └── assets/                # 画像等のリソース（必要な場合）
```

- フォルダ名はテーマ名にする。既に同名フォルダがある場合は中身を確認し、上書きより更新・追加を優先する。
- 各ファイルの冒頭に、所属テーマフォルダ内での役割（教科書本体 / 検証レポート / 調査メモ 等）を明記する。
- 画像等の添付ファイルは `assets/` に置き、Markdownからは相対パスで参照する。

## 手順

1. **テーマフォルダの作成**
   - ユーザーが指定したテーマに基づき、`{テーマ名}/` フォルダを作成し、`README.md` を置く。
   - `README.md` にはテーマ名、対象読者・レベル、想定学習時間、章立て、進行状況（未着手/作成中/検証済み/PDF化済み）を記録する。以後の各工程で内容を更新する。

2. **テーマの把握**
   - テーマ、対象読者・レベル（初級/中級/上級）、想定学習時間を確認する。
   - 不明な場合は質問して確定する。特に「対象レベル」と「章数（分量）」は必ず確認する。

3. **全体構成の設計**
   - テーマを分解して目次（章立て）を設計する。目次案をユーザーに提示して承認を得てから本文の生成を開始する。
   - 目次には以下の項目を必ず含める:
     - 序章またははじめに（本書の使い方）
     - テーマの基礎を学ぶ章（用語と概念の定義）
     - 主要概念を深掘りする章（段階的に難易度を上げる）
     - 実践・応用の章（具体的な適用例）
     - 総まとめの章
     - 付録: 練習問題の解答、用語集

4. **各章の構成**
   各章は以下の要素を持つ:
   - `#` 章見出し、`##` 節見出し、`###` 項見出し
   - 学習目標: 章の冒頭に「この章で学ぶこと」を箇条書きで提示
   - 本文: 概念を説明し、重要な用語は `**太字**` で強調
   - 図解・例示: 概念を具体的な例で説明。必要に応じてASCIIアートやMarkdown表、コードブロックを使う
   - 本章のまとめ: 章末に要点を箇条書きで整理
   - 練習問題: 章末に問題を配置する

5. **練習問題**
   - 各章に3〜5問の練習問題を設ける。選択式・穴埋め・記述式を混ぜる。
   - 問題番号は章ごとに振り直す（例: 第2章の問題1→`練習問題 2.1`）。
   - 解答は巻末の付録にまとめる。解答には解説を付ける。
   - テーマに関連する資格・試験（例: 基本情報技術者、簿記検定、FP技能検定等）がある場合は、それらを調べて明記し、正解率と資格取得相当レベルの対応を示す（下記参照）。

5-2. **資格との対応（関連資格がある場合のみ）**
   - テーマに関連する資格・試験を websearch で調査し、以下の基準で本文に記載する:
     - **資格名・主催・合格基準**: 資格の正式名称、実施団体、合格に必要な正解率（公開されている場合）を明記する。
     - **正解率と資格相当の対応**: この教科書の練習問題の正解率がどの程度なら、その資格の取得相当とみなせるかを示す。目安は以下:
       - 正解率 90%以上: 合格十分レベル（模擬試験合格相当）
       - 正解率 70〜89%: 合格レベル（受験可能・合格圏内）
       - 正解率 50〜69%: 基礎習得レベル（要復習）
       - 正解率 50%未満: 未習得（章の復習が必要）
   - 実際の合格基準が公開されている場合は、その基準を基準として、教科書の問題正解率との対応を明記する（例: 「実際の試験は60%が合格ライン。本書で70%以上なら合格相当」）。
   - 記載は各章の練習問題の直後、または巻末の付録に「資格対応」欄としてまとめる。
   - 対象読者に資格が関係ない（学校の科目や趣味の学習など）場合はこの記載を省略してよい。

6. **用語集**
   - 本文全体から重要用語を集め、付録に「用語集」としてまとめる。
   - 用語→定義の順で、50音順またはアルファベット順に整列する。

7. **出力形式**
   - 教科書本体は `{テーマ名}/教科書.md` として保存する。
   - ファイル冒頭にタイトル、対象読者、レベル、想定学習時間、目次を置く。
   - 目次には各章へのリンク（`# 章名` への `[章名](#...)`）を付ける。リンク先アンカーは GitHub風slug（小文字化、空白→`-`、記号除去）にし、**見出しテキストと対応させて漏れなく書く**。最終的なリンクの一致確認は印刷用HTML変換時（`print-formatting` スキル）に自動で行われるため、Markdown段階では見出しが正しく並んでいることを重視する。
   - 長大になる場合は章ごとに分割し、`README.md` に目次兼インデックスを置く案を提示する。
   - 作成後、`README.md` の進行状況を「作成中」に更新する。

## 品質基準

- 誤りや誤解を招く記述を避け、事実に基づいた内容にする。不確かな事実は出典や注記を添える。
- 読者のレベルに合わせた語彙・説明の深さにする（初級なら専門用語に必ず説明を添える）。
- 同じ概念を章をまたいで矛盾なく説明する。
- 学習者目線で、具体例→抽象化の順で説明する。

```markdown
| {資格名} | {実施団体} | {合格ライン} | 練習問題の正解率 {70%} 以上 |

- 正解率 90%以上: 合格十分レベル / 70〜89%: 合格レベル / 50〜69%: 基礎習得レベル / 50%未満: 要復習

**練習問題 1.1** 解答: ...

### 用語集

- **{用語}**: {定義}
```
